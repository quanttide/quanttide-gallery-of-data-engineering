# 数据规格（约束合同）

> 本层把数据意图落成数据源、表结构、计算口径、流程步骤、质量校验与追溯矩阵，是计算机实现的约束。本层不写具体语言与工具。

## 数据源与采集规则

| 项 | 规则 |
|:--|:--|
| 平台 | 天猫、京东 |
| 关键词 | 1000 余个，按官方 CPI 分类组织 |
| 频率 | 每日一次 |
| 字段 | 商品标识、名称、分类、价格、销量、采集时间 |
| 落盘 | 按日分区；单个关键词失败不影响其余 |
| 约束 | 只读抓取、限速重试、不采集个人数据 |

## 清洗与归一化规则

- 统一时间格式（按日）、价格单位（元）与分类编码（官方 CPI 分类）。
- 商品到分类的映射以分类清单为准，映射缺失的记录计入异常。
- 同一商品同一日出现多条记录时，保留最后一条有效记录。
- 有效价格与异常判定按「数据意图」的操作定义执行，本层不另立定义。

## 表结构

| 表 | 内容 |
|:--|:--|
| `category` | 分类：分类编码、名称、上级分类、权重 |
| `product` | 商品：商品标识、平台、名称、分类编码、状态 |
| `price_daily` | 每日价格与销量：商品标识、日期、价格、销量、是否有效 |
| `index_daily` | 日度指数：分类编码、日期、平均价格、环比、指数 |

## 指标计算口径

- 分母、阈值与分组口径均以「数据意图」的指标定义为准。
- 分类平均价格按销量加权；销量缺失或为 0 的商品不参与加权。
- 链式指数以上一期为基期，基期指数取 100。
- 聚合维度：全局、按分类、按平台三层。

## 流程步骤

| 步骤 | 输入 | 处理规则 | 产物 | 验收 |
|:--|:--|:--|:--|:--|
| 采集 | 关键词清单 | 按平台抓取，按日分区落盘 | 原始日分区 | 关键词覆盖与记录数核对 |
| 清洗 | 原始日分区 | 归一化、映射、去重、有效性判定 | `price_daily` | 有效记录率与异常占比核对 |
| 计算 | `price_daily` | 分类加权均价、环比、链式指数 | `index_daily` | 断点为 0，指数为正 |
| 校验 | `index_daily` | 断点与异常波动检查 | 校验报告 | 断点为 0，异常逐条说明 |
| 发布 | `index_daily` | 输出日度指数与趋势图 | 指数文件、图表 | 与 `index_daily` 数值一致 |

## 质量校验

- 采集后核对关键词覆盖与记录数。
- 清洗后核对有效记录率与异常占比。
- 计算后核对指数连续率与断点。
- 发布后核对发布产物与 `index_daily` 数值一致。

## 追溯矩阵

层级 ID 为 `REQ-001` / `INT-001` / `SPEC-001`，断言 ID 形如 `INT-001-H2`；每行一条链路，逐列可回指、反向可查。

| 发布产物 | 命题 | 数据意图指标 | 业务成功指标 |
|:--|:--|:--|:--|
| 日度指数 | INT-001-H1 | 商品覆盖率、指数波动 | 覆盖商品数、数据可用率 |
| 日度指数 | INT-001-H2 | 异常占比、指数波动 | 数据可用率 |
| 指数序列 | INT-001-H3 | 指数连续率 | 指数连续率 |
| 校验报告 | 全部命题 | 全部数据意图指标 | 全部业务成功指标 |

# 数据工程案例：量潮搜索工程

## 定位

量潮搜索工程管理从「信息在哪」到「把它取出来」这一段：可索引化、索引的建立与更新、查询解析、召回、排序与质量评测。本案例用「需求 → 哲学意图 → 数学形式化验证 → 计算机实现」四层链路，把「搜索效率低」这类模糊判断，转成可追溯、可证伪、可复现的数据产物。

> 不直接问搜索乱不乱。先把搜索拆成可观测的动作，再把动作变成可计算的指标，最后把指标变成可复现的诊断。

## 四层框架

| 层级 | 核心问题 | 输出 |
|:--|:--|:--|
| 需求 | 为什么做、什么算成功 | 目标、成功指标、范围、非目标 |
| 哲学意图 | 到底在谈什么、凭什么说它是问题 | 本体、视角、问题树、假设 |
| 数学形式化验证 | 怎么定义、怎么算、怎么验收 | 变量、指标、命题、约束 |
| 计算机实现 | 具体怎么做出来 | 数据、代码、管道、报告 |

## 需求层

多个智能体的搜索行为不稳定，影响任务成功率与使用者信任。目标是定位搜索低效的主因、形成可验证的改进方向；成功指标是产出可复现的诊断报告、识别主要失败模式；范围是近三个月若干智能体会话；非目标是本次不重写检索算法。

## 哲学意图层

搜索被看作任务目标、信息需求、工具预算与反馈信号下的决策过程。乱不是搜索次数多，而是相对于任务目标的查询漂移、重复搜索、结果未利用与过度搜索。核心问题是低效来自查询生成、检索环境、结果利用，还是策略与目标；视角取控制论、信息检索与因果解释。

## 数学形式化验证层

操作定义分四组。结果质量含空结果率、错误率、结构化结果占比；结果体量含结果字符数的中位数、P90、最大值与过载率；行为模式含连续搜索率、搜完又搜未行动率、会话内重复查询率、搜索后读文件率；成本含延迟中位数。

命题 H1：空结果率高的会话更易失败。H2：连续搜索与结果未被消费正相关。H3：结果过载与有效命中率负相关。验收要求每个指标可复现、每个命题可证伪。

## 计算机实现层

1. 采集：把 6 个来源的会话库汇入统一原始区；
2. 清洗：归一化成统一形状，产出会话、消息、工具调用、搜索事件四张表，并标注消息与搜索的相关性；
3. 分析：计算上节指标，按来源与会话汇总；
4. 报告：程序生成 Markdown 诊断报告。

## 脱敏说明

必须脱敏的有四类：个人与渠道标识（飞书 chat_id 与 open_id、微信 openid、用户 ID）、凭据与密钥（API key、token、bot 与 app id）、本机绝对路径、以及会话编号（以会话 A、B、C 代替）。其余保留：智能体与工具名称、计数与比例、失败模式与指标定义。

## 工作原则

1. 先概念，后指标；
2. 先定义，后计算；
3. 先可证伪，后自动化；
4. 全链可追溯；
5. 可复现、可争论、可验收。

---

## 结语

需求是价值承诺，哲学意图是概念承诺，数学形式化是验证承诺，计算机实现是执行承诺。从需求到实现，每一步都可追溯、可质疑、可复现。

> 不是查数，是建构可验证的认知。

# 量潮搜索工程

量潮搜索工程负责解决从「信息在哪」到「把它取出来」：可索引化、索引的建立与更新、查询解析、召回、排序与质量评测。本案例按「数据需求 → 数据意图 → 数据规格 → 数据实现」四层链路展开（一般框架见[首页](../index.md)），把「搜索效率低」这类模糊判断，转成可追溯、可证伪、可复现的数据产物。

## 数据需求

### 背景与痛点

多个智能体（pi、zed、hermes、hermes-backup、dsh、opencode）的搜索行为不稳定：同样的任务，有的会话几次搜索即命中，有的会话反复搜索仍拿不到可用结果。搜索低效直接拖低任务成功率，并消耗使用者对智能体的信任。

### 目标与非目标

- 目标：定位搜索低效的主因，形成可验证的改进方向，产出一份可复现的诊断。
- 非目标：本次不重写检索算法；不覆盖非搜索类工具的低效；不追求指标的全覆盖。

### 成功指标（业务口径）

成功不以「产出报告」计，而以业务后果的改善计。下列指标在本次诊断中先建立基线，后续迭代再对照改善；具体阈值与显著性判据在「数据意图」层以统计检验定义。

| 指标 | 口径 | 目标方向 |
|:--|:--|:--|
| 搜索相关失败率 | 含搜索会话中，因搜索失败导致任务失败的占比 | 相对基线下降 |
| 任务成功率 | 含搜索任务中，会话达成目标动作的占比 | 相对基线提升 |
| 低效会话占比 | 单会话搜索次数超过阈值的会话占比 | 相对基线下降 |
| 结果采纳率 | 搜索之后结果被后续动作消费的比率 | 相对基线提升 |

### 范围

- 来源：6 个智能体——pi、zed、hermes、hermes-backup、dsh、opencode。
- 时间：近三个月的会话。
- 对象：上述来源中全部含搜索工具调用的会话及其搜索事件。
- 版本：各来源取诊断期内的全部版本，不做版本切分。

### 利益相关者

| 角色 | 关心什么 |
|:--|:--|
| 研发 | 修复工具与提示词缺陷 |
| 算法 | 改进查询生成与召回 |
| 产品 | 决定搜索体验改进的优先级 |
| 使用者 | 任务能否一次做对 |

### 约束

- 数据权限：会话数据含个人与渠道标识，须按[首页](../index.md)「脱敏说明」脱敏后方可产出。
- 合规：凭据与密钥不得进入任何分析产物。
- 只读：不改动源数据。
- 一次性：本次为离线诊断，不引入在线系统改动。

## 数据意图

数据意图层把「搜索效率低」这一模糊判断转成形式化验证：界定对象、给出操作定义、建立指标、提出可证伪命题、指定验证方法，并登记验证结论。本层不涉及数据表、字段、代码与工具。

### 形式化对象

| 对象 | 记号 | 说明 |
|:--|:--|:--|
| 会话 | s | 一次完整交互 |
| 轨迹 | τ = (a₁, a₂, …) | 会话内的动作序列 |
| 动作 | a | 一次工具调用 |
| 搜索事件 | e | τ 中被判定为搜索的动作 |
| 查询 | q | 搜索事件的输入 |
| 结果 | r | 搜索事件的返回 |

变量与随机变量：查询 q；结果特征——条数 n、是否为空 ∅、是否错误 ϵ、字符数 ℓ、是否可结构化 ρ；行为特征——连续次序 k、结果后首个非搜索动作、是否行动前再搜；时延 Δt。任务目标 g 与工具预算 B 作为外部给定。

### 操作定义

- **搜索判定**：一次工具调用满足任一条件即计为搜索——工具名 ∈ 搜索工具集（search_files、session_search、memory_search、grep、glob、find、find_path、list_directory、search）；或工具为 shell 类（terminal、bash、shell、run_terminal_cmd）且命令行匹配搜索动词（grep、rg、ripgrep、find、fd、locate、ag、ack、ls、tree、which、whereis）。
- **查询漂移** drift(q, g)：查询与任务目标的语义相似度低于阈值 δ。
- **结果被消费** consume(e)：结果之后的首个非搜索动作读用了该结果（读文件、引用等）。
- **结果未利用**：结果被消费为假。
- **过度搜索**：单会话或单目标内的搜索次数超过工具预算 B。
- **有效命中率**：结果非空、非错误且被消费的搜索 ÷ 搜索总数。

### 指标

分母默认为搜索总数，空结果率除外。

| 指标 | 定义 |
|:--|:--|
| 空结果率 | 结果条数为 0 的搜索 ÷ 能解析出结果条数的搜索 |
| 错误率 | 返回错误的搜索 ÷ 搜索总数 |
| 结构化结果占比 | 结果可解析为 JSON 的搜索 ÷ 搜索总数 |
| 结果体量 | 结果字符数 ℓ 的中位数、P90、最大值 |
| 过载率 | ℓ 不小于阈值（默认 8000）的搜索 ÷ 搜索总数 |
| 连续搜索率 | 连续次序 k > 0 的搜索 ÷ 搜索总数 |
| 搜完又搜未行动率 | 在调用非搜索工具前再次搜索的搜索 ÷ 搜索总数 |
| 会话内重复查询率 | 同一会话内归一化查询出现两次及以上的搜索 ÷ 搜索总数 |
| 搜索后读文件率 | 结果之后首个动作是读文件的搜索 ÷ 搜索总数 |
| 延迟中位数 | 结果时间戳与调用时间戳之差的中位数 |

聚合维度：全局、按来源、按会话三层，便于把结论下钻到具体来源与会话。

### 命题与假设

失败 fail(s) 定义为会话未达到目标动作。

| 假设 | 内容 | 可证伪条件 |
|:--|:--|:--|
| H1 | 空结果率高的会话更易失败 | 空结果率与任务失败呈负相关或无关 |
| H2 | 连续搜索与结果未被消费正相关 | 连续搜索率与未消费率不相关 |
| H3 | 结果过载与有效命中率负相关 | 过载率与有效命中率不相关或正相关 |

### 因果图

```
prompt_version → query_drift → result_unused → task_fail
retrieval_env  → query_drift
tool_budget    → result_unused
```

混杂变量：任务类型、来源、会话长度。H1–H3 目前是相关命题，因果方向须经识别策略确认（见「验证方法」）。

### 约束与不变量

- 搜索次数 ≤ 工具预算 B。
- 查询与任务目标的相似度 ≥ δ，否则记为漂移。
- 结果引用覆盖 ≥ γ。

### 验证方法

- 假设：零假设 H0 与备择假设 H1–H3。
- 统计检验：比例用两比例 z 检验，相关用 Spearman 或卡方；报告效应量与置信区间。
- 样本量：按基线效应量估算，控制 I 类错误。
- 偏差控制：按来源与任务类型分层，避免辛普森悖论。
- 因果识别：可行时用提示词版本的 A/B，或用反事实/断点回归；不可识别时只报告相关。

## 数据规格

数据规格层是数据意图的具象，也是计算机实现的约束。它把形式化验证中的对象、定义、指标、命题，落成数据源、表结构、计算口径、流程步骤、质量校验与追溯矩阵。本层不写具体语言与工具。

### 数据源与采集规则

- 来源：pi、zed、hermes、hermes-backup、dsh、opencode。
- 每个来源登记本地位置与格式（消息型、编码型、编辑器、终端等）。
- 能导出为 JSONL 的来源用其导出命令落盘，其余直接复制原始文件，统一写入 `data/raw/<来源>/`。
- 采集后写 `data/raw/manifest.json`，记录每个来源的路径、会话计数与采集时间。
- 约束：只读复制，不改动源数据；单个来源失败不影响其余来源。

### 清洗流程与归一化规则

- 归一化把每个来源的会话转换成统一形状：会话携带元数据（编号、来源、标题、模型、起止时间）与消息列表；assistant 消息携带工具调用（工具名与参数），工具结果消息携带调用编号与结果文本。不同来源的工具调用结构差异在此抹平。
- 搜索判定与特征抽取按「数据意图」的操作定义执行，本层不另立定义。

### 表结构

产物为四张 Parquet 表：

| 表 | 内容 |
|:--|:--|
| `sessions` | 会话元数据 |
| `messages` | 消息列表，带搜索相关标注 |
| `tool_calls` | 工具调用，参数已解析为对象 |
| `search_events` | 搜索事件，附查询、结果与行为特征 |

同时写清洗清单 `manifest.json`，记录四表行数与按来源的搜索计数。

### 指标计算口径

- 分母、阈值与分组口径均以「数据意图」的指标定义为准。
- 聚合维度：全局、按来源、按会话三层。
- 空结果率分母为能解析出结果条数的搜索，其余指标分母默认为搜索总数。

### 流程步骤

分析拆成五步：采集、清洗、分析、验证、报告。每一步固定输入、处理规则与产物，换一台机器也能重跑出同样的结构。

| 步骤 | 输入 | 处理规则 | 产物 | 验收 |
|:--|:--|:--|:--|:--|
| 采集 | 各来源本地会话数据 | 按来源登记位置与格式，只读复制或导出为 JSONL | `data/raw/<来源>/`、`manifest.json` | 行数与来源计数核对 |
| 清洗 | 原始区 | 归一化为四张表，按操作定义判定搜索与抽取特征 | `sessions`、`messages`、`tool_calls`、`search_events`、清洗清单 | 四表行数与搜索计数核对 |
| 分析 | 搜索事件表 | 按指标定义与聚合维度计算 | 指标 JSON、报告 Markdown | 报告与 JSON 数值一致 |
| 验证 | 指标与搜索事件表 | 对 H1–H3 执行检验，含效应量与置信区间；可行时因果识别 | 检验结果 | 统计量、p 值、效应量、置信区间齐全 |
| 报告 | 指标 JSON、检验结果 | 固定章节：总览、按来源、结果质量、结果体量、行为模式、搜索后首个动作分布、每会话摘要、诊断与证据强度 | Markdown 报告 | 结论可回指到具体指标与命题 |

### 质量校验

- 采集后核对 manifest 行数。
- 清洗后核对四表行数与搜索计数。
- 分析后核对报告与 JSON 数值一致。
- 验证后核对检验结果与指标口径一致。

### 追溯矩阵

层级 ID 为 `REQ-001` / `INT-001` / `SPEC-001` / `IMP-001`，断言 ID 形如 `INT-001-H2`；每行一条链路，逐列可回指、反向可查。总览、按来源与每会话摘要为下列链路的聚合视图，不另立指标。

| 报告章节 | 命题 | 数据意图指标 | 业务成功指标 |
|:--|:--|:--|:--|
| 结果质量 | INT-001-H1 | 空结果率、错误率、结构化结果占比 | 搜索相关失败率、任务成功率 |
| 结果体量 | INT-001-H3 | 结果体量、过载率 | 低效会话占比 |
| 行为模式 | INT-001-H2 | 连续搜索率、搜完又搜未行动率、会话内重复查询率 | 低效会话占比 |
| 搜索后首个动作分布 | INT-001-H2 | 搜索后读文件率 | 结果采纳率 |
| 诊断与证据强度 | INT-001-H1–H3 | 全部数据意图指标 | 全部业务成功指标 |

## 数据实现

数据实现层给出一条可复现的工程路径。技术栈为 Python 与 polars，中间产物用 Parquet，同一条命令行工具贯穿采集、清洗、分析与报告。

### 技术栈

- 语言：Python。
- 数据处理：polars。
- 中间产物：Parquet。
- 报告：Markdown。

### 数据管道

按「数据规格」的流程步骤实现采集、清洗、分析、验证、报告五步。每步的输入、处理规则与产物以数据规格为准，本层只写具体代码与工具。

### 命令行入口

复现命令依次为：

1. `load`：采集。
2. `clean`：清洗。
3. `analyze`：分析并产出指标 JSON 与报告 Markdown。
4. `verify`：对 H1–H3 执行统计检验并落盘检验结果。

### 质量校验脚本

- 采集后核对 manifest 行数。
- 清洗后核对四表行数与搜索计数。
- 分析后核对报告与 JSON 数值一致。
- 验证后核对检验结果与指标口径一致。

### 版本管理

数据、代码、报告各自带上版本与时间戳。

### 执行验证

对 H1–H3 按「数据意图」的验证方法执行：计算检验统计量、效应量与置信区间；可行时做因果识别（提示词版本 A/B 或反事实），不可识别则只报相关。检验结论与原始指标一并落盘。

### 报告生成

报告固定包含：总览、按来源、结果质量、结果体量、行为模式、搜索后首个动作分布、每会话摘要（截断只展示前若干名），末尾附诊断与证据强度。报告与指标 JSON 一并写出，两者数值一致；任何结论都必须回指到具体指标与命题，不得由模型自由生成。

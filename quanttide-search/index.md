# 数据工程案例：量潮搜索工程

## 定位

量潮搜索工程管理从「信息在哪」到「把它取出来」这一段：可索引化、索引的建立与更新、查询解析、召回、排序与质量评测。本案例用「需求 → 哲学意图 → 数学形式化验证 → 计算机实现」四层链路，把「搜索效率低」这类模糊判断，转成可追溯、可证伪、可复现的数据产物。

> 不直接问搜索乱不乱。先把搜索拆成可观测的动作，再把动作变成可计算的指标，最后把指标变成可复现的诊断。

## 四层框架

| 层级 | 核心问题 | 输出 |
|:--|:--|:--|
| 需求 | 为什么做、什么算成功 | 目标、成功指标、范围、非目标 |
| 哲学意图 | 到底在谈什么、凭什么说它是问题 | 本体、视角、问题树、假设 |
| 数学形式化验证 | 怎么定义、怎么算、怎么验收 | 变量、指标、命题、约束 |
| 计算机实现 | 具体怎么做出来 | 数据、代码、管道、报告 |

## 需求层

多个智能体的搜索行为不稳定，影响任务成功率与使用者信任。目标是定位搜索低效的主因、形成可验证的改进方向；成功指标是产出可复现的诊断报告、识别主要失败模式；范围是近三个月若干智能体会话；非目标是本次不重写检索算法。

## 哲学意图层

搜索被看作任务目标、信息需求、工具预算与反馈信号下的决策过程。乱不是搜索次数多，而是相对于任务目标的查询漂移、重复搜索、结果未利用与过度搜索。核心问题是低效来自查询生成、检索环境、结果利用，还是策略与目标；视角取控制论、信息检索与因果解释。

## 数学形式化验证层

操作定义分四组。结果质量含空结果率、错误率、结构化结果占比；结果体量含结果字符数的中位数、P90、最大值与过载率；行为模式含连续搜索率、搜完又搜未行动率、会话内重复查询率、搜索后读文件率；成本含延迟中位数。

命题 H1：空结果率高的会话更易失败。H2：连续搜索与结果未被消费正相关。H3：结果过载与有效命中率负相关。验收要求每个指标可复现、每个命题可证伪。

## 计算机实现层

分析拆成固定四步：采集、清洗、分析、报告。每一步都固定输入、处理规则与产物，目的是换一台机器也能重跑出同样的结构，从而复现结论。技术栈为 Python 与 polars，中间产物用 Parquet。

### 第一步 采集

输入是各来源的本地会话数据，输出是统一原始区。

每个来源登记其本地位置与格式（消息型、编码型、编辑器、终端等不同类型）。能导出为 JSONL 的来源用其导出命令落盘，其余直接复制原始文件，统一写入 `data/raw/<来源>/`。采集后写 `data/raw/manifest.json`，记录每个来源的路径、会话计数与采集时间，用于核对完整性。约束是只读复制，不改动源数据；单个来源失败不影响其余来源。

### 第二步 清洗

输入是原始区，输出是归一化后的四张表。

归一化把每个来源的会话转换成统一形状：会话携带元数据（编号、来源、标题、模型、起止时间）与消息列表；assistant 消息携带工具调用（工具名与参数），工具结果消息携带调用编号与结果文本。不同来源的工具调用结构差异在此抹平。

搜索判定规则：一次工具调用满足以下任一条件即计为搜索——工具名属于搜索工具集（如 search_files、session_search、memory_search、grep、glob、find_path、list_directory），或工具为 shell 类（terminal、bash）且命令行匹配搜索动词（grep、rg、find、fd、ls、tree 等）。

特征抽取为每次搜索计算四组字段：统一查询字段（依次取 query、pattern、command、path）、归一化查询、结果特征（结果条数、是否为空、是否为错误、结果字符数、是否可结构化解析）、行为特征（在连续搜索串中的次序、结果之后的首个非搜索动作、是否在行动前再次搜索）以及调用到结果的时间差。

产物为四张 Parquet 表：会话表、消息表（带搜索相关标注）、工具调用表（参数已解析为对象）、搜索事件表（附上述特征）。同时写清洗清单，记录四表行数与按来源的搜索计数。

### 第三步 分析

输入是清洗后的搜索事件表，输出是指标 JSON。分母默认为搜索总数，空结果率除外。

| 指标 | 定义 |
|:--|:--|
| 空结果率 | 结果条数为 0 的搜索 ÷ 能解析出结果条数的搜索 |
| 错误率 | 返回错误的搜索 ÷ 搜索总数 |
| 结构化结果占比 | 结果可解析为 JSON 的搜索 ÷ 搜索总数 |
| 结果体量 | 对结果字符数取中位数、P90 与最大值 |
| 过载率 | 结果字符数不小于阈值（默认 8000）的搜索 ÷ 搜索总数 |
| 连续搜索率 | 位于连续搜索串中（次序大于 0）的搜索 ÷ 搜索总数 |
| 搜完又搜未行动率 | 在调用非搜索工具前再次搜索的搜索 ÷ 搜索总数 |
| 会话内重复查询率 | 同一会话内归一化查询出现两次及以上的搜索 ÷ 搜索总数 |
| 搜索后读文件率 | 结果之后首个动作是读文件的搜索 ÷ 搜索总数 |
| 延迟中位数 | 结果时间戳与调用时间戳之差的中位数 |

聚合维度为全局、按来源、按会话三个层级，便于对失败定位到下钻到具体来源与会话。

### 第四步 报告

输入是指标 JSON，输出是 Markdown 报告。报告固定包含七节：总览、按来源、结果质量、结果体量、行为模式、搜索后首个动作分布、每会话摘要（截断只展示前若干名），末尾附自动生成的初步诊断。报告与指标 JSON 一并写出，两者数值一致，任何口头结论都可回指到具体指标。

复现入口是同一条命令行工具的三个子命令：先采集、再清洗、再分析，依次执行即可从本地会话数据得到报告。

## 脱敏说明

对外发布前需脱敏四类信息：个人与渠道标识（飞书 chat_id 与 open_id、微信 openid、用户 ID）、凭据与密钥（API key、token、bot 与 app id）、本机绝对路径、以及会话编号。其余可保留：智能体与工具名称、计数与比例、失败模式与指标定义。

## 工作原则

1. 先概念，后指标；
2. 先定义，后计算；
3. 先可证伪，后自动化；
4. 全链可追溯；
5. 可复现、可争论、可验收。

---

## 结语

需求是价值承诺，哲学意图是概念承诺，数学形式化是验证承诺，计算机实现是执行承诺。从需求到实现，每一步都可追溯、可质疑、可复现。

> 不是查数，是建构可验证的认知。
